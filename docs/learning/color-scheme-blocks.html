dark 블록이 두 개인 이유

tokens.css에는 dark Semantic 변수가 똑같은 내용으로 두 번 나온다. 한 번은 @media (prefers-color-scheme: dark) 안에, 한 번은 :root[data-color-scheme="dark"]에 있다. dark가 되어야 하는 상황이 두 가지인데 CSS는 미디어 쿼리와 selector를 "또는"으로 묶을 수 없어서다. OS 설정과 <html> 태그의 경우의 수를 모두 펼쳐 놓고 어느 블록이 적용되는지 본다.

한눈에 보기

tokens.css의 Semantic 부분은 블록 세 개다. 변수 줄은 줄였다. 

/* light 블록: 기본값 */
:root {
  color-scheme: light;
  --gyeol-bg-surface: var(--gyeol-color-white);
  /* … */
}

/* media 블록: OS가 dark이고 사이트에서 light를 고르지 않았을 때 */
@media (prefers-color-scheme: dark) {
  :root:not([data-color-scheme="light"]) {
    color-scheme: dark;
    --gyeol-bg-surface: var(--gyeol-color-gray-950);
    /* … */
  }
}

/* 속성 블록: 사이트에서 dark를 골랐을 때 (OS 설정과 상관없음) */
:root[data-color-scheme="dark"] {
  color-scheme: dark;
  --gyeol-bg-surface: var(--gyeol-color-gray-950);
  /* … media 블록과 한 줄도 다르지 않다 */
}

이 노트에서는 세 블록을 selector의 생김새대로 light 블록(:root), media 블록(@media 안의 dark), 속성 블록(:root[data-color-scheme="dark"])으로 부른다.

dark가 되는 두 가지 상황

Color Scheme을 정하는 입력은 두 가지다. OS의 설정(웹뷰라면 네이티브 앱의 설정)과 <html>의 data-color-scheme 속성이다. 속성은 사이트가 "이 사이트는 이 Color Scheme으로 보여 달라"고 직접 고를 때 붙인다. 이 두 입력으로 dark가 되는 길이 두 갈래다.

media 블록: OS 설정을 따른다
  1. OS가 dark
  2. 사이트에서 light를 고르지 않음
  3. dark
속성 블록: 사이트에서 고른 값을 따른다
  1. 사이트에서 dark를 고름
  2. OS 설정은 보지 않음
  3. dark

조건으로 쓰면 이렇다.

dark = (OS가 dark 그리고 속성이 light가 아님) 또는 (속성이 dark)
       └────────── media 블록 ──────────┘       └ 속성 블록 ┘
  • @media (prefers-color-scheme: dark)는 "OS가 dark"를 뜻한다. 미디어 쿼리가 거짓이면 브라우저는 그 안의 규칙을 없는 것처럼 다룬다.
  • :not([data-color-scheme="light"])는 "속성이 light가 아님"을 뜻한다. 속성이 없거나 dark면 맞는다.
  • :root[data-color-scheme="dark"]는 미디어 쿼리 밖에 있어서 OS 설정과 상관없이 맞는다.

한 블록으로 합칠 수 없는 이유

CSS에서 "또는"을 만드는 방법은 두 가지다. 그런데 어느 것도 "미디어 쿼리 또는 selector"를 만들지 못한다.

쓰는 법 묶을 수 있는 것 여기서 쓸 수 있나
.a, .b { } selector끼리 없음 "OS가 dark"는 selector로 쓸 수 없다
@media (a), (b) { } 미디어 쿼리끼리 없음 "속성이 dark"는 미디어 쿼리로 쓸 수 없다

미디어 쿼리는 selector가 아니라 규칙 전체를 감싸는 바깥 조건이다. 그래서 아래 같은 문법은 없다. 

/* 이런 문법은 없다 */
@media (prefers-color-scheme: dark), :root[data-color-scheme="dark"] {
  /* … */
}

남는 방법은 미디어 쿼리 안의 규칙(media 블록)과 밖의 규칙(속성 블록)으로 나누는 것뿐이다. 그래서 dark 변수 목록이 두 번 나온다.

이 중복은 사람이 맞춰 고칠 대상이 아니다. tokens.css는 빌드 결과물이고, 빌드 스크립트가 semantic/dark.json 하나를 읽어 두 블록에 같은 내용을 찍어 낸다. 원본은 한 곳뿐이다.

여섯 가지 경우

OS 설정 2가지 × <html> 태그 3가지(<html>, <html data-color-scheme="light">, <html data-color-scheme="dark">)로 경우는 모두 여섯 가지다. 경우마다 어느 블록이 맞고 왜 그 결과가 나오는지 표로 보면 이렇다.

OS 설정 <html> 태그 맞는 블록 결과
light <html> light 블록 media 블록은 미디어 쿼리가 거짓, 속성 블록은 속성이 없다 light
light <html data-color-scheme="light"> light 블록 light
light <html data-color-scheme="dark"> light 블록, 속성 블록 명시도가 높은 속성 블록이 이긴다 dark
dark <html> light 블록, media 블록 명시도가 높은 media 블록이 이긴다 dark
dark <html data-color-scheme="light"> light 블록 media 블록은 :not([data-color-scheme="light"])에 걸려 빠진다 light
dark <html data-color-scheme="dark"> light 블록, media 블록, 속성 블록 media 블록과 속성 블록의 내용이 같아 어느 쪽이 이겨도 결과가 같다 dark

한 문장으로 줄이면 속성이 있으면 속성을, 없으면 OS 설정을 따른다.

확인 방법: 실제 빌드한 tokens.css를 Chrome 155에 넣고 경우마다 <html>의 --gyeol-bg-surface와 color-scheme을 읽었다. light는 #ffffff, dark는 #09090b가 나왔다. OS 설정은 페이지에서 바꿀 수 없어서, OS light는 @media 블록을 지운 CSS로, OS dark는 @media (…) { 감싸기만 벗긴 CSS로 확인했다. 미디어 쿼리가 거짓일 때와 참일 때 브라우저가 보는 규칙과 같다.

명시도

한 요소에 여러 블록이 맞으면 명시도(selector의 점수)가 높은 쪽이 이긴다. 명시도가 같으면 뒤에 나온 쪽이 이긴다. 미디어 쿼리는 점수에 들어가지 않는다.

블록 selector 명시도 계산
light 블록 :root (0,1,0) 가상 클래스 1개
media 블록 :root:not([data-color-scheme="light"]) (0,2,0) :root 1개 + :not() 안의 속성 selector 1개 :not() 자체는 점수가 없고 괄호 안의 점수를 가져온다
속성 블록 :root[data-color-scheme="dark"] (0,2,0) :root 1개 + 속성 selector 1개

dark 블록은 둘 다 (0,2,0)이라 light 블록(0,1,0)을 블록 순서와 관계없이 이긴다. media 블록과 속성 블록은 명시도가 같지만 내용이 같아서 어느 쪽이 이겨도 결과가 같다.

:not()이 media 블록의 명시도를 올려 주는 것은 덤이다. 미디어 쿼리는 점수에 들어가지 않으므로, :not()이 없다면 media 블록은 light 블록과 같은 (0,1,0)이 되고 뒤에 나온다는 이유로만 이긴다.

다른 방법: light-dark()

CSS light-dark() 함수를 쓰면 값을 한 번만 적을 수 있다. 이 함수는 요소의 color-scheme이 light면 첫 값, dark면 둘째 값을 쓴다. color-scheme: light dark는 "둘 다 되니 OS 설정을 따르라"는 뜻이다. 

:root {
  color-scheme: light dark;
  --gyeol-bg-surface: light-dark(var(--gyeol-color-white), var(--gyeol-color-gray-950));
}
:root[data-color-scheme="light"] { color-scheme: light; }
:root[data-color-scheme="dark"] { color-scheme: dark; }

"또는"을 color-scheme 속성 하나가 대신 맡는 구조다. Chrome 155에서 <html>, <html data-color-scheme="light">, <html data-color-scheme="dark">가 각각 OS 설정(확인한 기기는 light), light, dark로 나왔다.

점검 문제

1. 속성 블록의 selector를 :root[data-color-scheme="dark"]에서 [data-color-scheme="dark"]로 바꾸면 여섯 경우의 결과가 달라지나?

"명시도" 절을 바탕으로, <html>에 붙인 속성만 생각한다. 

-:root[data-color-scheme="dark"] {
+[data-color-scheme="dark"] {
   color-scheme: dark;
답 보기

여섯 경우의 결과는 같다. [data-color-scheme="dark"]의 명시도는 (0,1,0)으로 light 블록과 같아지지만, 속성 블록이 light 블록보다 뒤에 있어서 여전히 이긴다. 대신 블록 순서에 기대게 되고, <section data-color-scheme="dark">처럼 하위 요소에서 dark만 동작하고 light는 동작하지 않는 비대칭이 생긴다. 지금 :root로 묶은 이유다.

2. 사이트에 "OS 설정 따르기 / light / dark" 세 가지 선택지를 두려고 한다. "OS 설정 따르기"를 고르면 <html>을 어떻게 해야 하나?

"여섯 가지 경우" 절의 표를 본다.

답 보기

data-color-scheme 속성을 지운다. 속성이 없으면 OS light에서는 light 블록, OS dark에서는 media 블록이 맞아 OS 설정을 따른다. JS가 OS 설정을 읽을 필요가 없고, OS 설정이 바뀌면 브라우저가 미디어 쿼리를 다시 판정해 바로 따라간다.

쓰인 곳

  • packages/tokens/scripts/build-tokens.ts의 SCHEME_SELECTORS: Color Scheme마다 블록의 selector 목록. dark에 selector 묶음이 두 개 있어서 dark 블록이 두 번 나온다
  • packages/tokens/scripts/build-tokens.helper.ts의 wrapInColorSchemeBlock: 변수 줄을 selector 묶음 안에 넣고 @media처럼 중첩된 블록을 들여 쓴다
  • packages/tokens/scripts/build-tokens.test.ts: 세 블록의 selector와, data-color-scheme 속성이 <html>에서만 동작하는지 단언하는 테스트
  • packages/tokens/README.md "Color Scheme 고르기": 사용자가 보는 속성 사용법과 블록 표

출처

여섯 경우와 light-dark() 예시는 실제 빌드한 tokens.css로 Chrome 155에서 직접 확인했다.

  • MDN, prefers-color-scheme: OS나 사용자 에이전트의 light/dark 설정을 읽는 미디어 기능
  • MDN, @media: 미디어 쿼리 목록을 쉼표로 묶는 문법과, 조건이 거짓일 때 안의 규칙이 적용되지 않는 동작
  • MDN, Specificity: 명시도 계산과 :not()이 괄호 안의 명시도를 가져오는 규칙
  • MDN, :not(): 괄호 안의 selector에 맞지 않는 요소를 고르는 가상 클래스
  • MDN, light-dark(): color-scheme에 따라 두 색 중 하나를 고르는 함수와 브라우저 지원
  • MDN, color-scheme: 요소가 어느 Color Scheme으로 그려질 수 있는지 알리는 속성
