Style Dictionary로 토큰을 CSS로 빌드하기

packages/tokens/scripts/build-tokens.ts의 buildTokens는 토큰 JSON을 읽어 CSS 텍스트를 돌려주는 함수다. 이 함수가 Style Dictionary에 넘기는 옵션을 하나씩 뜯어 보고, 옵션을 바꾸면 출력이 어떻게 달라지는지 직접 실행한 결과로 보여 준다.

한눈에 보기

파란 줄은 buildTokens 안에서 일어나는 일이다. 파일을 읽고 문자열을 돌려줄 뿐 파일을 기록하지 않는다. 초록 줄은 pnpm build가 이 함수를 실제 토큰 폴더로 불러 결과를 파일로 기록하고, tsdown이 dist/를 채우는 흐름이다.

buildTokens(토큰 폴더)
  1. primitive.json을 읽어 객체로 만든다
  2. new StyleDictionary(설정)
  3. formatPlatform("css")
  4. { css: ":root { … }" }를 돌려준다
pnpm build
  1. build.ts: buildTokens("tokens/")
  2. build.ts: generated/tokens.css에 기록한다
  3. tsdown: dist/를 비우고 dist/index.js를 만든다
  4. tsdown: generated/tokens.css를 dist/로 복사한다

파일 기록을 함수 밖(build.ts)으로 뺀 이유는 테스트다. 테스트는 fixture 폴더로 buildTokens를 부르고 돌려받은 문자열만 검사한다. 디스크에 아무것도 남기지 않는다.

Style Dictionary가 하는 일

Style Dictionary는 플랫폼 중립의 토큰 JSON 하나를 플랫폼마다 다른 모양(CSS 변수, iOS Swift 상수, Android XML 등)으로 바꾸는 빌드 도구다. 바꾸는 일은 아래 순서로 나뉘고, 설정의 옵션은 각 단계에 무엇을 할지 알려 준다.

  1. 토큰 읽기 tokens(객체)나 source(파일 경로)로 받은 JSON을 합친다. $value가 보이면 DTCG 형식으로 판단한다. 우리 설정에서 sd.usesDtcg는 true였다.
  2. 플랫폼 고르기 platforms의 키 하나(우리는 css)를 골라 그 플랫폼의 설정으로 아래 단계를 돈다.
  3. transform 토큰마다 이름(name), 값(value), 속성(attribute)을 바꾼다. 예를 들어 색 객체를 #18181b로, 경로 color.gray.900을 gyeol-color-gray-900으로 바꾼다.
  4. 참조 해석 {color.gray.900} 같은 참조를 실제 값으로 바꾼다. Primitive에는 참조가 없어 이번 티켓에서는 일이 없다. 참조가 풀려야 transform할 수 있는 값이 있어서 transform과 번갈아 여러 번 돈다.
  5. format transform이 끝난 토큰 목록을 파일 내용(문자열) 하나로 만든다. css/variables는 :root { --이름: 값; }을 만든다.
  6. 기록 문자열을 buildPath + destination 파일로 기록한다. buildTokens는 이 단계를 부르지 않는다.

스크립트를 위에서부터

1. 결과의 모양

import { readFile } from "node:fs/promises";
import { join } from "node:path";
import StyleDictionary from "style-dictionary";
import type { DesignTokens } from "style-dictionary/types";

export interface BuildResult {
  /** `tokens.css`의 내용 */
  css: string;
}

const PREFIX = "gyeol";
  • BuildResult는 돌려줄 값의 모양이다. 지금은 css 하나지만, spec(#16)은 TS 소스도 함께 돌려주도록 정했다(#22에서 ts가 더해진다). 그래서 문자열 대신 객체로 돌려준다.
  • PREFIX는 모든 CSS 변수 이름 앞에 붙는다. --gyeol-은 docs/architecture.md의 규칙이다.
  • DesignTokens는 Style Dictionary가 내보내는 토큰 트리 타입이다. 런타임에는 사라지는 import type이다.

2. 토큰 파일을 직접 읽는다

export async function buildTokens(tokensDir: string): Promise<BuildResult> {
  // 파일 경로를 Style Dictionary의 source 옵션으로 넘기지 않고 직접 읽는다.
  // source의 항목은 경로 하나라도 glob 패턴으로 풀리고, 맞는 파일이 0개여도 오류가 아니다.
  // 그러면 토큰 없이 빌드가 끝나 빈 ":root {}"가 나온다. 직접 읽으면 파일이 없을 때 ENOENT로 실패한다.
  const primitivePath = join(tokensDir, "primitive.json");
  const primitive: DesignTokens = JSON.parse(
    await readFile(primitivePath, "utf8"),
  );

Style Dictionary에 파일 경로를 넘겨도 읽어 준다. 그런데도 직접 읽는 이유는 tokens와 source에서 실험으로 보인다. 짧게 말하면, 경로가 틀려도 Style Dictionary는 오류 없이 빈 :root를 낸다. readFile은 파일이 없으면 ENOENT로 실패한다.

3. Style Dictionary 설정

  const sd = new StyleDictionary({
    tokens: primitive,
    log: { verbosity: "silent" },
    platforms: {
      css: {
        prefix: PREFIX,
        // 실제로 일하는 transform은 name/kebab(이름), color/css(hex, rgba()), size/rem(dimension)이다.
        //
        // size/rem은 이름과 달리 px를 rem으로 바꾸지 않는다. unit이 적혀 있으면 그대로 붙이고
        // ({16, "px"} → "16px"), unit 없는 숫자에만 "rem"을 붙인다. 토큰은 모두 px로 쓰므로 px로 나온다.
        // size/px를 직접 고르지 않는 이유: size/px는 unit을 무시해 {1.5, "rem"}도 "1.5px"로 낸다.
        transformGroup: "css",
        files: [
          {
            destination: "tokens.css",
            format: "css/variables",
          },
        ],
      },
    },
  });

칠한 줄이 옵션이다. 각 옵션이 하는 일은 아래 표와 같다.

옵션 값 하는 일
tokens 읽은 객체 빌드할 토큰 트리 tokens와 source
log.verbosity "silent" Style Dictionary의 콘솔 출력을 끈다 log.verbosity
platforms.css 설정 객체 "css"라는 이름의 출력 하나. 이름은 우리가 정한다 platforms와 prefix
prefix "gyeol" 변수 이름 앞에 붙일 말
transformGroup "css" CSS용으로 미리 묶어 둔 transform 14개를 쓴다 transformGroup과 transforms
files[].destination "tokens.css" Style Dictionary가 파일을 기록할 경로 formatPlatform은 파일을 기록하지 않아서 돌려받는 값에 이름표로만 붙는다. 빼도 출력은 같다. 실제 기록은 build.ts가 한다
files[].format "css/variables" 토큰 목록을 :root { … } 문자열로 만든다 files: format과 options

4. 문자열만 받아 돌려준다

  const [file] = await sd.formatPlatform("css");
  if (typeof file?.output !== "string") {
    throw new Error("Style Dictionary가 tokens.css를 만들지 못했다");
  }
  return { css: file.output };
}

formatPlatform은 files의 항목마다 { output, destination }을 담은 배열을 돌려준다. 우리는 파일이 하나라 첫 항목만 꺼낸다. output의 타입은 문자열이 아닐 수도 있게 넓게 선언되어 있어서, 문자열인지 확인한 뒤 돌려준다. 자세한 내용은 formatPlatform에 있다.

토큰 하나가 CSS 한 줄이 되기까지

primitive.json의 토큰 하나는 이름과 값이 따로 바뀐 뒤 --이름: 값; 한 줄로 합쳐진다. 아래 값은 getPlatformTokens("css")로 transform이 끝난 토큰을 꺼내 확인한 것이다.

이름 ["color", "gray", "900"]경로 name/kebab + prefix gyeol-color-gray-900
색 값 { srgb, [0.0941, 0.0941, 0.1059] }DTCG 색 객체 color/css #18181b
alpha 있는 색 { srgb, [0, 0, 0], alpha: 0.5 } color/css rgba(0, 0, 0, 0.5)
dimension { value: 16, unit: "px" }DTCG dimension 객체 size/rem 16px 적힌 unit을 그대로 붙인다
합치기 이름 + 값 css/variables --gyeol-color-gray-900: #18181b;

완성된 변수 이름을 부분으로 나누면 이렇다.

--gyeol-color-gray-900 --는 css/variables format이 붙이고, 나머지는 name/kebab transform이 prefix와 경로를 -로 이어 만든다.

transform이 빠지면 Style Dictionary는 객체를 그대로 문자열로 바꿔 [object Object]를 낸다. 오류가 나지 않으니 출력을 봐야 안다. 설정을 바꾸면 나오는 CSS의 C 줄이 그 경우다.

경로가 틀리면 빌드가 바로 실패한다. 우리가 고른 방법이다.

"파일이 없으면 오류 없이 빈 결과"는 없는 경로를 source에 넣고 실행해 확인했다. Style Dictionary는 source의 항목마다 globSync(패턴)으로 맞는 파일 목록을 구한다(lib/utils/combineJSON.js). 와일드카드 없는 경로도 패턴 하나로 다루고, glob은 "맞는 파일이 0개"를 오류가 아닌 빈 목록으로 돌려준다. 이 동작은 테스트 "토큰 폴더에 primitive.json이 없으면 실패한다"가 지킨다.

나중에 semantic/light.json이 더해져도 같은 방식으로 직접 읽는다. 검증 규칙(#21)도 읽은 객체를 보고 판단해야 하므로, 읽는 일을 우리 코드가 갖는 편이 낫다.

platforms와 prefix

platforms는 "같은 토큰으로 만들 출력"의 목록이다. 키는 우리가 정하는 이름이고, 값은 그 출력의 설정이다. CSS와 iOS를 함께 낸다면 css와 ios 두 키를 둔다. 지금은 CSS만 내므로 키가 하나다. formatPlatform("css")의 "css"가 이 키를 가리킨다.

prefix는 플랫폼 설정의 하나라 플랫폼마다 다르게 줄 수 있다. 이름을 만드는 transform(name/kebab)이 경로 앞에 붙인다.

설정 color.gray.900의 변수 이름
prefix: "gyeol" + name/kebab --gyeol-color-gray-900
prefix 없음 + name/kebab --color-gray-900
prefix: "gyeol" + name/camel --gyeolColorGray900
prefix: "gyeol" + 이름 transform 없음 prefix도 붙지 않는다 --900 충돌 위험

마지막 줄처럼 이름 transform이 없으면 경로의 마지막 조각만 이름이 되고, prefix도 쓰이지 않는다. spacing.4는 --4, radius.md는 --md가 되어 다른 범주의 같은 이름과 부딪힌다.

transformGroup과 transforms

transform은 토큰 하나를 받아 이름, 값, 속성 중 하나를 바꾸는 함수다. 두 옵션 중 하나로 고른다.

  • transforms: ["name/kebab", "color/css", …]: 쓸 transform을 직접 나열한다.
  • transformGroup: "css": Style Dictionary가 CSS용으로 묶어 둔 목록을 쓴다. 우리가 고른 방법이다.

transform마다 filter가 있어서, 맞는 토큰에만 걸린다. 예를 들어 color/css는 $type이 color인 토큰에만 걸린다. 그래서 group에 필요 없는 transform이 들어 있어도, 맞는 토큰이 없으면 아무 일도 하지 않는다. 아래 표는 css group의 14개 transform의 filter를 fixture 토큰에 직접 대 본 결과다.

transform 바꾸는 것 fixture에서 걸린 토큰 빼면
attribute/cti 속성 모두 CSS는 같다 경로를 {category, type, item}으로 적어 둘 뿐이다
name/kebab 이름 모두 --white, --900, --4
color/css 값 color 3개 색이 [object Object]
size/rem 값 spacing.4, radius.md 크기가 [object Object]
time/seconds, html/icon, asset/url, fontFamily/css, cubicBezier/css 값 없음 CSS는 같다
strokeStyle, border, typography, transition, shadow의 /css/shorthand 값 없음 CSS는 같다

실제로 일을 하는 것은 name/kebab, color/css, size/rem 세 개다. 나머지는 typography나 shadow 토큰이 생길 때 쓰인다. 직접 세 개만 나열해도 지금 출력은 같지만, 표준 묶음을 쓰면 Style Dictionary 문서와 바로 맞춰 읽을 수 있다.

size/rem과 size/px

gyeol-ui는 dimension을 모두 px로 쓰고 CSS에도 px로 낸다. 그런데 쓰는 transform 이름이 size/rem이라 반직관적이다. 이름만 보면 px를 rem으로 바꿀 것 같지만 그렇지 않다. 처음 구현에서 이렇게 잘못 알고 size/px를 골랐다가, 실행해 보고 바로잡았다. 그래서 코드에도 이 내용을 주석으로 적어 두었다. 두 transform에 같은 토큰 세 개를 넣은 결과다.

files: format과 options

files는 플랫폼 하나에서 만들 파일의 목록이다. 항목마다 어떤 format으로 만들지(format), 어디에 쓸지 (destination), format에 넘길 옵션(options)을 적는다. 같은 토큰으로 CSS 파일 두 개를 만들고 싶으면 항목을 두 개 둔다.

css/variables format

transform이 끝난 토큰을 하나씩 --이름: 값; 줄로 만들어 선택자 블록 하나에 담는다. 기본값 그대로 둔 옵션과, 다음 티켓에서 쓸 옵션은 아래와 같다.

옵션 기본값 바꾸면
showFileHeader true false면 맨 위의 /** Do not edit directly, this file was auto-generated. */ 주석이 빠진다 기본값 그대로 둔다. 고정 문구라 snapshot이 빌드마다 바뀌지 않고, 배포되는 dist/tokens.css를 직접 고치지 말라는 표시가 된다. #19에서 Color Scheme별 결과를 이어 붙이면 헤더가 반복되므로 첫 결과에만 남긴다
selector :root "[data-x]"를 주면 블록이 [data-x] { … }로 나온다 #19의 Color Scheme 블록([data-color-scheme="dark"] 등)에 쓸 수 있다
outputReferences false true면 참조를 값으로 풀지 않고 var(--…)로 낸다 #19에서 Semantic을 낼 때 쓴다. Primitive에는 참조가 없다

formatPlatform

설정을 만든 뒤 빌드를 시작하는 메서드는 여럿이다. 무엇을 돌려주고 파일을 기록하는지가 다르다.

메서드 돌려주는 것 파일 기록
buildAllPlatforms() 없음 기록함 모든 플랫폼
buildPlatform("css") 없음 기록함 플랫폼 하나
formatPlatform("css") [{ output, destination }] 파일마다 하나 안 함
getPlatformTokens("css") transform이 끝난 토큰 목록 (allTokens 등) 안 함

buildTokens는 "CSS 텍스트를 돌려주는" 함수라 formatPlatform이 맞다. 실험에서 buildPath를 빈 폴더로 주고 formatPlatform만 불렀을 때 폴더가 생기지 않았다. getPlatformTokens는 이 노트의 토큰 하나가 CSS 한 줄이 되기까지에서 transform 결과를 들여다볼 때 썼다.

설정을 바꾸면 나오는 CSS

  • Style Dictionary, Predefined formats: css/variables와 showFileHeader, selector, outputReferences 옵션
  • Style Dictionary, API: formatPlatform, buildPlatform, getPlatformTokens
  • Style Dictionary, DTCG support: $value로 DTCG 형식을 알아보는 동작
