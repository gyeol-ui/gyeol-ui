Tailwind @theme inline이 하는 일

@gyeol-ui/tailwind의 theme.css는 @theme이 아니라 @theme inline으로 시작한다. inline은 Tailwind가 빌드할 때 클래스 규칙에 테마 변수의 이름을 적을지 값을 적을지를 바꾼다. 이 차이가 브라우저에서 CSS 변수가 상속되는 방식과 만나면 결과 색이 달라진다. 빌드 단계, 생성된 CSS, 요소마다의 변수 값을 실제로 컴파일하고 측정한 결과로 따라간다.

한눈에 보기

같은 테마 줄 하나가 inline 유무에 따라 이렇게 다른 CSS가 된다(bg-bg-surface를 쓴 경우).

@theme inline (지금) @theme
클래스 규칙 background-color: var(--gyeol-bg-surface) background-color: var(--background-color-bg-surface)
:root에 생기는 변수 없음 --background-color-bg-surface: var(--gyeol-bg-surface)
:root 아래에서 --gyeol-bg-surface를 바꾸면 클래스가 바뀐 값을 따른다 클래스는 :root의 값에 머문다

세 줄의 이유를 차례로 본다. 테마 변수가 무엇인지, Tailwind가 빌드할 때 그것으로 무엇을 하는지, inline이 그중 어디를 바꾸는지, 그 결과가 브라우저에서 왜 다르게 보이는지다.

theme variable

Tailwind v4의 theme variable은 @theme 블록 안에 적는 --이름: 값 한 줄이다. CSS 변수처럼 생겼지만, 어떤 유틸리티 클래스가 생길지를 정하는 설정이다. :root에 적은 일반 CSS 변수로는 클래스가 생기지 않는다. 

:root {
  --brand: #3b82f6;         /* 일반 CSS 변수: bg-brand는 생기지 않는다 */
}

@theme {
  --color-brand: #3b82f6;   /* theme variable: bg-brand, text-brand … 가 생긴다 */
}

이름의 앞부분(namespace)이 어떤 유틸리티가 이 변수를 쓸지 정하고, 나머지가 클래스 이름이 된다.

--background-color-bg-surface: var(--gyeol-bg-surface) bg- 유틸리티가 찾는 namespace라서 bg-bg-surface가 생긴다
theme variable 생기는 클래스
--color-brand bg-brand, text-brand, border-brand …색 유틸리티 전부
--background-color-bg-surface bg-bg-surface배경색 유틸리티만
--spacing-4 p-4, m-4, gap-4 …
--radius-md rounded-md

이 저장소의 테마 변수는 값이 모두 토큰 CSS 변수(var(--gyeol-…))를 가리킨다. 실제 색과 길이는 @gyeol-ui/tokens의 tokens.css에 있다.

Tailwind가 @theme으로 하는 일

@theme 블록은 브라우저가 읽는 CSS가 아니다. Tailwind가 빌드할 때 읽고 출력에서 지운다. 빌드는 이렇게 진행된다.

  1. import 펼치기 @import "tailwindcss"와 @import "@gyeol-ui/tailwind"(→ theme.css → tokens.css)를 하나의 CSS로 합친다.
  2. 테마 표 만들기 모든 @theme 블록을 모아 메모리에 키와 값의 표를 만든다. Tailwind 기본 테마가 먼저 들어가고, 뒤의 블록이 덮어쓰거나 initial로 지운다. @theme inline 블록에서 온 항목에는 inline 표시가 붙는다.
  3. 쓰인 클래스 찾기 소스에서 bg-bg-surface, p-4 같은 후보를 모은다. 쓰지 않은 클래스는 만들지 않는다.
  4. 클래스 규칙 쓰기 클래스마다 테마 표에서 항목을 찾아 규칙을 쓴다. 이때 항목의 inline 표시를 본다. 다음 절에서 자세히 본다.
  5. 쓰인 테마 변수 출력 4에서 규칙이 이름으로 가리킨 항목만 @layer theme의 :root에 CSS 변수로 출력한다. 기본으로는 쓰인 변수만 나온다.
  6. 이어 붙이기 preflight, 만든 유틸리티, tokens.css 내용을 이어 붙인다. @theme 블록 자체는 출력에 없다.

2에서 만들어지는 테마 표는 이런 모양이다(일부).

키 값 inline 표시 어디서 왔나
--background-color-bg-surface var(--gyeol-bg-surface) 있음 theme.css
--spacing-4 var(--gyeol-spacing-4) 있음 theme.css
--font-sans -apple-system, BlinkMacSystemFont, … 없음 Tailwind 기본 테마
--color-red-500 지워짐theme.css의 --color-*: initial Tailwind 기본 테마

inline이 바꾸는 한 가지

inline은 빌드의 4단계만 바꾼다. 클래스 규칙에 테마 항목의 키 이름을 적느냐, 값을 복사해 붙이느냐다. 5단계의 :root 출력은 그 선택을 따라온다. 테마 줄 하나를 두 방식으로 끝까지 따라가면 다음과 같다.

  1. 빌드 (Tailwind)
  2. theme.css테마 줄 
    --background-color-bg-surface: var(--gyeol-bg-surface);
  3. 2. 테마 표블록 앞의 inline 유무가 항목의 표시로 남는다.
  4. @theme inline 
    키   --background-color-bg-surface
값   var(--gyeol-bg-surface)
표시 inline
    @theme 
    키   --background-color-bg-surface
값   var(--gyeol-bg-surface)
표시 없음
  5. 4. 규칙 쓰기bg-bg-surface가 이 항목을 찾았다. inline이면 값을, 아니면 키 이름을 적는다.
  6. @theme inline값을 붙였다 
    .bg-bg-surface {
  background-color: var(--gyeol-bg-surface);
}
    @theme키 이름을 적었다 
    .bg-bg-surface {
  background-color: var(--background-color-bg-surface);
}
  7. 5. 변수 출력규칙이 키 이름을 가리키면 그 이름의 변수가 화면에 있어야 하므로 :root에 출력한다.
  8. @theme inline@layer theme 
    :root, :host {
  /* 토큰 관련 변수 없음 */
}
    @theme@layer theme 
    :root, :host {
  --background-color-bg-surface: var(--gyeol-bg-surface);
}

실제 dist/theme.css로 bg-bg-surface와 p-4를 컴파일한 결과에서 해당 부분만 옮겼다.

--font-sans 등 preflight가 쓰는 기본 변수만. 토큰 관련 변수 없음

클래스가 토큰 변수를 직접 읽는다.

클래스가 Tailwind 변수를 거쳐 토큰 변수를 읽는다.

브라우저에서 생기는 차이

한 단계 더 거칠 뿐이라 결과가 같아 보인다. 차이는 브라우저가 CSS 변수를 계산하는 방식에서 나온다.

CSS 변수(--*)는 상속된다. 그리고 변수의 계산된 값은 그 변수를 선언한 요소에서 안의 var()를 바꿔 넣은 값이다. 그래서 자식 요소는 var() 식이 아니라 이미 바꿔 넣은 값을 물려받는다.

@theme에서는 --background-color-bg-surface가 :root에 선언된다. 그래서 그 안의 var(--gyeol-bg-surface)는 :root의 값으로 한 번 바뀌고, 모든 요소가 그 결과를 물려받는다. 아래는 프로모션 영역에서만 --gyeol-bg-surface를 노란색으로 바꾼 HTML이다. 

<section style="--gyeol-bg-surface: #fde68a">
  <div class="bg-bg-surface p-4">프로모션 카드</div>
</section>

두 테마로 만든 CSS에서 요소마다 변수 값을 Chrome으로 읽었다.

오른쪽 div의 --gyeol-bg-surface는 노란색인데도 배경은 흰색이다. 클래스가 읽는 --background-color-bg-surface는 :root에서 이미 #ffffff로 정해져 내려왔다.

Tailwind 문서도 같은 이유로, 다른 변수를 가리키는 테마 변수에는 inline을 쓰라고 안내한다. 문서의 예는 글꼴이다. --font-sans: var(--font-inter)를 부모에, 실제 --font-inter를 자식에 두면 var(--font-sans)가 부모에서 풀려 Inter가 아닌 대체 글꼴이 나온다.

경우마다 측정한 결과

같은 페이지에 카드 셋을 두고 배경색을 getComputedStyle로 읽었다. light는 <html>에 속성이 없을 때, dark는 <html data-color-scheme="dark">일 때다.

카드 @theme inline @theme
light dark light dark
페이지 카드토큰을 바꾸지 않음 #ffffff #09090b #ffffff #09090b
프로모션 카드부모 section에서 #fde68a로 #fde68a #fde68a #ffffff무시됨 #09090b무시됨
자기 자신에서 바꾼 카드카드의 style에서 #bbf7d0으로 #bbf7d0 #bbf7d0 #ffffff무시됨 #09090b무시됨

light/dark 전환은 두 테마 모두 된다. dark 블록이 Tailwind 변수와 같은 요소(:root)에서 --gyeol-bg-surface를 바꾸므로, --background-color-bg-surface가 계산될 때 이미 dark 값이다. 차이는 :root보다 아래에서 토큰을 바꿀 때만 생긴다. 카드 자신의 style에서 바꿔도 무시되는 것은, 카드가 읽는 변수가 --gyeol-bg-surface가 아니라 물려받은 --background-color-bg-surface이기 때문이다.

이 저장소가 inline을 쓰는 이유

gyeol-ui는 Theme(브랜드별 토큰 세트)을 지원하지 않고, Color Scheme도 <html>에서만 바꾼다. 그래서 공식으로 지원하는 기능만 쓰면 위 표의 "무시됨" 경우는 생기지 않는다. 그런데도 inline을 쓰는 이유는 셋이다.

  1. 공개 CSS 변수를 --gyeol-* 한 벌로 둔다 docs/architecture.md의 Tailwind 테마 규칙이다. inline이 없으면 --background-color-bg-surface, --spacing-4 같은 변수가 사용자 화면의 :root에 생긴다. 같은 값을 가리키는 이름이 두 벌이 되고, 사용자가 어느 쪽을 써야 하는지, 바꾸려면 어느 쪽을 바꿔야 하는지 헷갈린다.
  2. 클래스가 var(--gyeol-…)를 직접 쓴 것과 똑같이 동작한다 bg-bg-surface는 손으로 쓴 background-color: var(--gyeol-bg-surface)와 글자까지 같은 규칙이 된다. 사용자가 자기 CSS에서 토큰 변수를 다시 정의하면 Tailwind 클래스와 직접 쓴 CSS가 함께 따라간다. inline이 없으면 둘 중 클래스만 조용히 따라가지 않는다. 오류 없이 색만 틀어지는 종류라 미리 막는다.
  3. Tailwind가 권하는 쓰임이다 이 테마의 값은 모두 다른 변수(var(--gyeol-…))를 가리킨다. Tailwind 문서는 이런 테마 변수에 inline을 쓰라고 안내한다.

포기한 것은 사용자가 자기 CSS에서 var(--background-color-bg-surface)처럼 Tailwind 변수를 쓰는 방법이다. 같은 값은 var(--gyeol-bg-surface)로 쓸 수 있으므로 잃는 것이 거의 없고, 쓸 이름이 하나로 정해진다.

점검 문제

1. 테마를 @theme(inline 없음)으로 두고 아래 HTML을 그리면 div의 padding은 몇 px인가? --gyeol-spacing-4의 원래 값은 16px이다.

"inline이 바꾸는 한 가지"의 .p-4 규칙과 "브라우저에서 생기는 차이"의 상속 규칙을 쓴다. 

<section style="--gyeol-spacing-4: 20px">
  <div class="p-4">…</div>
</section>
답 보기

16px이다. .p-4는 padding: var(--spacing-4)이고, --spacing-4: var(--gyeol-spacing-4)는 :root에서 16px로 계산되어 내려온다. div의 --gyeol-spacing-4는 20px이지만 규칙이 읽지 않는다. Chrome에서 같은 HTML로 확인한 값도 16px이다. 지금의 @theme inline이면 20px이다.

2. 테마 변수의 값이 토큰 변수가 아니라 실제 색이라면 어떻게 될까? 아래처럼 바꾸고, section에서 Tailwind 변수 쪽을 다시 정의했다.

"inline이 바꾸는 한 가지"의 4단계를 값이 리터럴인 경우에 대입한다. 

-  --background-color-bg-surface: var(--gyeol-bg-surface);
+  --background-color-bg-surface: #ffffff;
<section style="--background-color-bg-surface: #fde68a">
  <div class="bg-bg-surface">…</div>
</section>
답 보기

이번에는 inline이 아닌 쪽이 따라간다. @theme이면 규칙이 var(--background-color-bg-surface)라서 section에서 다시 정의한 #fde68a를 물려받는다. @theme inline이면 규칙에 값 #ffffff가 그대로 박혀서 무엇을 다시 정의해도 흰색이다. Chrome에서도 각각 rgb(253, 230, 138)과 rgb(255, 255, 255)였다.

inline은 "덮어쓰기에 강하다"가 아니라 "규칙이 무엇을 읽느냐"를 바꾼다. 이 저장소에서는 사용자가 바꿀 곳을 --gyeol-*로 정했으므로, 규칙이 --gyeol-*를 직접 읽게 하는 inline이 맞다.

쓰인 곳

  • packages/tailwind/scripts/format-theme.ts의 formatTheme: 테마 텍스트를 "@theme inline {"으로 시작한다
  • packages/tailwind/dist/theme.css: 빌드한 테마. @theme inline 블록 안의 테마 변수가 모두 var(--gyeol-…)를 가리킨다
  • packages/tailwind/scripts/format-theme.test.ts: 컴파일한 클래스의 선언이 var(--gyeol-…)인지 확인한다. 테마가 inline이 아니면 var(--background-color-…)가 나와 실패한다
  • docs/architecture.md "Tailwind 테마": @theme inline을 쓰고 공개 CSS 변수를 --gyeol-* 한 벌로 둔다는 규칙과, 직접 확인한 사실

출처

컴파일 결과는 이 저장소의 dist/theme.css를 @tailwindcss/node 4.3.5로 컴파일해 얻었다. inline이 없는 경우는 첫 줄만 @theme {로 바꿨다. 요소마다의 변수 값과 배경색, 점검 문제의 답은 두 결과 CSS를 Chrome 155에 넣고 getComputedStyle로 읽었다.

  • Tailwind CSS, What are theme variables?: theme variable이 어떤 유틸리티 클래스가 있을지를 정하는 @theme 안의 특별한 CSS 변수라는 것, Theme variable namespaces: namespace와 유틸리티의 대응
  • Tailwind CSS, Referencing other variables: 다른 변수를 가리키는 테마 변수에 inline을 쓰라는 안내, 유틸리티가 테마 변수 대신 그 값을 쓴다는 것, 글꼴 예
  • Tailwind CSS, Generating all CSS variables: 기본으로는 쓰인 CSS 변수만 출력된다는 것
  • W3C, CSS Custom Properties for Cascading Variables Level 1, Defining Custom Properties: 사용자 정의 속성은 상속되고(Inherited: yes), 계산된 값은 변수를 바꿔 넣은 값이다(Computed value: specified value with variables substituted)
