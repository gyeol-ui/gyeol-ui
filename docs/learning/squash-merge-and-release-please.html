release-please의 다음 버전

지난 릴리스 뒤에 어떤 PR들이 merge되면 다음 버전이 몇이 되는지, 시나리오별로 따라가 본다. 시나리오는 모두 PR 제목이 그대로 main의 커밋 제목이 되는 squash merge를 가정한다.

계산 규칙

  1. 지난 릴리스 뒤의 커밋을 모은다 main에 push될 때마다, 마지막 릴리스 태그 이후의 커밋을 다시 읽어 릴리스 PR을 열거나 고친다.
  2. 커밋마다 제목의 type을 본다 fix, deps → patch
    feat → minor
    type 뒤에 !가 붙은 것(예: feat!) → major
    docs, chore, ci, build → 버전과 무관
  3. 가장 큰 변경 하나만 골라 버전을 한 번 올린다 커밋이 열 개여도 버전은 한 번만 오른다. patch는 0.1.0 → 0.1.1, minor는 0.1.0 → 0.2.0, major는 0.1.0 → 1.0.0이다.

시나리오 1. 문서와 CI만 고쳤다

지금 버전은 0.1.0이다. README를 고치고 CI 설정을 바꾼 PR만 merge했다.

지난 릴리스 뒤 main에 들어온 커밋 release-please가 읽는 변경
docs: README에 설치 방법 추가 버전과 무관
ci: Node 버전을 24로 올림 버전과 무관
chore: 의존성 정리 버전과 무관
0.1.0지금 버전 변경 없음 릴리스 PR이 열리지 않는다

시나리오 2. 버그만 두 개 고쳤다

지금 버전은 0.1.0이다. 버그를 고친 PR 두 개를 merge했다.

지난 릴리스 뒤 main에 들어온 커밋 release-please가 읽는 변경
fix(tokens): 간격 토큰 단위 수정 patch
fix(react): Button의 focus 링 색 수정 patch
0.1.0지금 버전 patch 0.1.1 0.1.2가 아니다. 한 번만 오른다

시나리오 3. 기능과 버그 수정이 섞였다

지금 버전은 0.1.0이다. 버그 수정, 새 기능, 잡일 PR이 차례로 merge됐다.

지난 릴리스 뒤 main에 들어온 커밋 release-please가 읽는 변경
fix(tokens): 간격 토큰 단위 수정 patch
feat(tokens): 색 토큰 추가 minor
chore: 의존성 정리 버전과 무관
0.1.0지금 버전 minor 0.2.0 가장 큰 변경이 minor다. 0.1.1을 거치지 않는다

시나리오 4. 0.x에서 API를 깨뜨렸다

지금 버전은 0.1.0이다. Button의 prop 이름을 바꿔 기존 코드가 깨지는 PR과 버그 수정 PR을 merge했다.

지난 릴리스 뒤 main에 들어온 커밋 release-please가 읽는 변경
feat(react)!: Button의 variant 이름 변경 major
fix(react): Button의 focus 링 색 수정 patch
옵션 없음 0.1.0지금 버전 major 1.0.0
bump-minor-pre-major 0.1.0지금 버전 major를 minor로 0.2.0

옵션이 없으면 아직 API를 다듬는 중인 0.x에서도 breaking 커밋 하나로 곧바로 1.0.0이 된다. bump-minor-pre-major를 켜면 1.0.0 미만에서는 breaking이 minor만 올린다.

시나리오 5. 0.x에서 기능을 patch로 올리고 싶다

시나리오 3과 같은 커밋이다. 이번에는 옵션에 따라 결과를 비교한다.

지난 릴리스 뒤 main에 들어온 커밋 release-please가 읽는 변경
fix(tokens): 간격 토큰 단위 수정 patch
feat(tokens): 색 토큰 추가 minor
chore: 의존성 정리 버전과 무관
옵션 없음 0.1.0지금 버전 minor 0.2.0
bump-patch-for-minor-pre-major 0.1.0지금 버전 minor를 patch로 0.1.1

bump-patch-for-minor-pre-major를 켜면 1.0.0 미만에서는 feat가 patch만 올린다. 두 옵션을 함께 켜면 0.x에서 breaking은 minor, feat와 fix는 patch가 된다. 1.x에서 major와 minor가 하던 일을 한 자리씩 내려 맡는 셈이다.

시나리오 6. 1.x에서 API를 깨뜨렸다

지금 버전은 1.2.3이다. 시나리오 4와 같은 커밋을 merge했다.

지난 릴리스 뒤 main에 들어온 커밋 release-please가 읽는 변경
feat(react)!: Button의 variant 이름 변경 major
fix(react): Button의 focus 링 색 수정 patch
옵션과 상관없이 1.2.3지금 버전 major 2.0.0

두 옵션은 1.0.0 미만에서만 작동한다. 1.x에서는 옵션을 켜도 결과가 같다. 같은 1.2.3에서 가장 큰 변경이 fix였다면 1.2.4, feat였다면 1.3.0이다.

한눈에 보기

지금 버전이 0.1.0일 때, 가장 큰 변경과 옵션 조합마다 다음 버전이다. 옵션 없음과 달라지는 칸을 굵게 표시했다.

가장 큰 변경 옵션 없음 bump-minor-pre-major bump-patch-for-minor-pre-major 둘 다
버전과 무관한 커밋만시나리오 1 릴리스 PR이 열리지 않는다
patch시나리오 2 0.1.1. 옵션과 상관없다
minor시나리오 3, 5 0.2.0 0.2.0 0.1.1 0.1.1
major시나리오 4 1.0.0 0.2.0 1.0.0 0.2.0

이 노트는 커밋 제목만 본다. 커밋 본문의 BREAKING CHANGE: footer나 changelog-sections 설정으로 릴리스 대상 type을 바꾸는 경우는 다루지 않는다. 0.x에서 어떤 옵션을 쓸지는 로드맵의 "릴리스 기반" 슬라이스에서 정한다.
