Tailwind @custom-variant로 dark: 다시 정의하기

@gyeol-ui/tailwind의 theme.css는 Tailwind의 dark:를 @custom-variant로 다시 정의해, 토큰의 Color Scheme 규칙과 같은 조건에서 켜지게 한다. 정의 블록의 &와 @slot이 어떻게 채워지는지, 그 결과로 나오는 표준 CSS 선택자(:where(), :root, *)가 무엇을 뜻하는지를 실제 컴파일 결과와 Chrome에서 확인한 매칭 결과로 따라간다.

왜 다시 정의하나

토큰 CSS(tokens.css)는 Semantic 색을 두 조건에서 dark 값으로 바꾼다. OS가 dark이고 <html>에 data-color-scheme="light"가 없을 때, 또는 <html data-color-scheme="dark">일 때다(dark 블록이 두 개인 이유). Tailwind 기본 dark:는 prefers-color-scheme만 본다. 그대로 두면 둘이 엇갈린다.

Tailwind 기본dark:
보는 것
OS 설정(prefers-color-scheme)만
<html data-color-scheme="light">, OS dark
켜짐
<html data-color-scheme="dark">, OS light
꺼짐

토큰 색은 light인데 dark: 스타일이 켜지거나, 그 반대가 된다.

다시 정의한 것@custom-variant dark
보는 것
OS 설정과 <html>의 속성
<html data-color-scheme="light">, OS dark
꺼짐
<html data-color-scheme="dark">, OS light
켜짐

토큰 색과 dark: 스타일이 언제나 같은 Color Scheme을 따른다.

variant

dark:, hover:, md:처럼 클래스 앞에 붙는 접두어가 variant다. variant는 유틸리티의 선언은 그대로 두고 언제 적용되는지만 바꾼다.

유틸리티 opacity-80항상 적용 dark: 붙이기 dark:opacity-80dark 조건에서만 적용

@custom-variant는 이 조건을 CSS로 직접 정의하는 Tailwind v4 지시어다. 이미 있는 이름(dark)으로 정의하면 기본 동작을 덮어쓴다.

@custom-variant의 두 형태

아래 출력은 모두 dark:opacity-80 하나를 @tailwindcss/node 4.3.5로 컴파일한 결과의 @layer utilities 부분이다.

한 줄 형태

조건이 선택자 하나로 끝날 때 쓴다. Tailwind 문서의 예다.

@custom-variant dark (&:where(.dark, .dark *));
.dark\:opacity-80:where(.dark, .dark *) {
  opacity: 80%;
}

블록 형태

@media로 감싸거나 갈래가 여럿일 때 쓴다. 블록 안에서 유틸리티의 선언이 들어갈 자리를 @slot으로 표시한다. 이 저장소의 정의다. 

@custom-variant dark {
  @media (prefers-color-scheme: dark) {
    &:where(:root:not([data-color-scheme="light"]), :root:not([data-color-scheme="light"]) *) { @slot; }
  }
  &:where(:root[data-color-scheme="dark"], :root[data-color-scheme="dark"] *) { @slot; }
}

블록에 @slot이 없으면 유틸리티의 선언이 버려진다. @custom-variant dark { &:where(.dark *) { color: red; } }로 dark:opacity-80을 컴파일하면 opacity: 80%는 사라지고 color: red만 나왔다. 오류도 나지 않는다.

&와 @slot이 채워지는 과정

정의 블록은 틀이고, 유틸리티 하나를 만들 때마다 두 자리가 채워진다. &에는 그 유틸리티의 선택자가, @slot에는 그 유틸리티의 선언이 들어간다. @slot이 두 번 나오면 규칙도 두 개 생기고, Tailwind는 중첩을 평탄하게 풀어 낸다.

  1. 컴파일 (Tailwind)dark:opacity-80을 만들 때
  2. 유틸리티opacity-80 
    선택자: .dark\:opacity-80
선언:   opacity: 80%;
    정의 블록theme.css 
    @media (prefers-color-scheme: dark) {
  &:where(…light 아님…) { @slot; }
}
&:where(…dark…) { @slot; }
  3. & ← 선택자, @slot ← 선언@slot 하나마다 규칙이 하나 생기고, 중첩된 &는 바깥 선택자에 붙여 평탄하게 푼다
  4. 출력표준 CSS 
    @media (prefers-color-scheme: dark) {
  .dark\:opacity-80:where(:root:not([data-color-scheme="light"]), :root:not([data-color-scheme="light"]) *) {
    opacity: 80%;
  }
}
.dark\:opacity-80:where(:root[data-color-scheme="dark"], :root[data-color-scheme="dark"] *) {
  opacity: 80%;
}
    비교: 기본 dark:다시 정의하기 전 
    @media (prefers-color-scheme: dark) {
  .dark\:opacity-80 {
    opacity: 80%;
  }
}

출력에는 &도 @slot도 남지 않는다. Tailwind 전용 문법은 컴파일 전의 theme.css에만 있고, 브라우저가 받는 CSS는 모두 표준 문법이다.

두 갈래와 경우의 수

출력의 두 규칙은 선언이 같다. 둘 중 하나라도 맞으면 스타일이 적용되므로 OR 조건이다.

갈래 켜지는 조건
① media 갈래 OS가 dark 이고 <html>이 data-color-scheme="light"가 아님
② 속성 갈래 <html data-color-scheme="dark"> (OS와 무관)

여섯 경우를 모두 펼치면 이렇다.

<html>의 data-color-scheme OS가 light OS가 dark
없음 꺼짐 켜짐 ①
"light" 꺼짐 꺼짐 ①이 :not으로 제외
"dark" 켜짐 ② 켜짐 ①②

토큰 CSS가 Semantic 색을 dark 값으로 바꾸는 경우와 칸마다 같다.

선택자 해부

속성 갈래의 선택자를 부분으로 나누면 이렇다.

.dark\:opacity-80:where(:root[data-color-scheme="dark"], :root[data-color-scheme="dark"] *) 클래스가 붙은 요소가, 괄호 안의 두 선택자 중 하나에도 맞으면 매칭된다.
부분 뜻
.dark\:opacity-80 클래스 이름 dark:opacity-80. :는 CSS에서 가상 클래스를 여는 글자라서 \:로 이스케이프한다. HTML에는 class="dark:opacity-80"로 쓴다
:where(A, B) A나 B 중 하나에 맞으면 매칭되는 가상 클래스. 명시도는 항상 0이다
:root 문서의 루트 요소. HTML 문서에서는 <html>이다
[data-color-scheme="dark"] 그 속성 값을 가진 요소
:not(X) X에 맞지 않는 요소. media 갈래에서 light를 뺄 때 쓴다
공백 자손 결합자. 왼쪽 요소 안에 있는(자식, 손자, 그 아래 모두) 오른쪽 요소
* 전체 선택자. 종류와 상관없이 아무 요소

모두 표준 CSS다. :where()는 Selectors Level 4에서 들어왔고, MDN 기준 2021년 1월부터 주요 브라우저에서 쓸 수 있다. Tailwind v4가 요구하는 브라우저(Chrome 111, Safari 16.4, Firefox 128)보다 이르므로, 이 선택자 때문에 지원 범위가 좁아지지 않는다.

:root와 :root *

속성은 <html>에서만 보는데 왜 자손(*)까지 넣을까. 두 가지가 서로 다른 것을 가리키기 때문이다.

  • 속성을 보는 곳은 :root[…], 즉 <html> 하나다.
  • 스타일을 받는 요소는 클래스가 붙은 & 자리의 요소이고, 페이지 어디에나 있다. :root[…] *는 그 요소가 그런 <html>의 자손인지 묻는다.

*를 빼면 dark:는 <html class="dark:…">에만 동작한다. :root만 빼면 아무 조상의 속성이나 보게 되어, 이 저장소가 지원하지 않는 "페이지 일부의 Color Scheme 바꾸기"가 된다. Chrome 155에서 element.matches()로 확인한 결과다. 

<html>                      <!-- 경우마다 속성을 바꾼다 -->
  <body>
    <img>                   <!-- 본문의 요소 -->
    <section>               <!-- 경우마다 속성을 바꾼다 -->
      <img>                 <!-- section 안의 요소 -->
경우 선택자 <html> 본문의 img section 안의 img
<html data-color-scheme="dark"> :where(:root[…], :root[…] *) 지금 형태 맞음 맞음 맞음
:root[…] * 없이 맞음 안 맞음 안 맞음
:where([…], […] *) :root 없이 맞음 맞음 맞음
<html>에는 없고 <section data-color-scheme="dark"> :where(:root[…], :root[…] *) 지금 형태 안 맞음 안 맞음 안 맞음
:where([…], […] *) :root 없이 안 맞음 안 맞음 맞음

<html>에만 속성이 있으면 지금 형태와 :root 없는 형태가 같다. 둘은 <section>에 속성을 달았을 때 갈린다. 지금 형태는 무시하고, 토큰 CSS도 Semantic 색을 :root에서만 바꾸므로 그 안의 토큰 색도 바뀌지 않는다. 그래서 dark:와 토큰 색이 엇갈리지 않는다.

*가 붙어도 느리지 않다. 이 규칙은 .dark\:opacity-80 클래스가 있는 요소에만 걸리고, * { … }처럼 모든 요소에 스타일을 거는 것이 아니다.

:where()와 명시도

:where()와 :is()는 매칭이 같고 명시도만 다르다.

:is(A, B)
매칭
A나 B
명시도
목록에서 가장 높은 선택자의 명시도

조건의 :root와 속성이 명시도를 올린다.

:where(A, B)
매칭
A나 B
명시도
항상 0

명시도는 앞의 클래스 하나만 센다.

같은 요소에 dark: 규칙과, 그 뒤에 오는 일반 클래스 .later { opacity: 0.5 }를 함께 걸고 <html data-color-scheme="dark">에서 Chrome 155의 getComputedStyle로 읽은 결과다. 명시도가 같으면 뒤에 온 규칙이 이긴다.

dark: 규칙의 선택자 명시도 결과 opacity
.v:where(:root[…], :root[…] *) 지금 형태 (0, 1, 0) 0.5 뒤의 .later가 이김. 일반 클래스 .v와 같음
.v:is(:root[…], :root[…] *) (0, 3, 0) 0.8 dark:가 이김
:root[…] .v 감싸지 않음 (0, 3, 0) 0.8 dark:가 이김

명시도가 높으면 dark: 클래스가 뒤에 오는 다른 클래스나 컴포넌트 스타일을 예상과 다르게 이긴다. :where()로 감싸면 dark: 클래스도 일반 유틸리티와 같은 규칙, 즉 같은 명시도에서 순서로 정해지는 규칙을 따른다.

다른 variant와 겹치기

variant를 쌓으면 조건이 차례로 덧붙고, @slot에는 맨 안쪽의 선언이 들어간다. 다시 정의한 dark:도 hover:, md:와 그대로 조합된다. 4.3.5로 컴파일한 결과다. 

/* dark:hover:opacity-80 */
@media (prefers-color-scheme: dark) {
  @media (hover: hover) {
    .dark\:hover\:opacity-80:where(:root:not([data-color-scheme="light"]), :root:not([data-color-scheme="light"]) *):hover {
      opacity: 80%;
    }
  }
}
@media (hover: hover) {
  .dark\:hover\:opacity-80:where(:root[data-color-scheme="dark"], :root[data-color-scheme="dark"] *):hover {
    opacity: 80%;
  }
}

md:dark:opacity-80은 두 갈래가 모두 @media (width >= 48rem) 안에 들어간다.

점검 문제

1. OS는 light이고 HTML이 아래와 같다. 두 img 중 opacity: 80%가 적용되는 것은?

"두 갈래와 경우의 수"의 표와 ":root와 :root *"의 표를 쓴다. 

<html>
  <body>
    <img id="a" class="dark:opacity-80">
    <section data-color-scheme="dark">
      <img id="b" class="dark:opacity-80">
    </section>
  </body>
</html>
답 보기

둘 다 적용되지 않는다. OS가 light라서 media 갈래(①)는 꺼져 있다. 속성 갈래(②)는 :root[data-color-scheme="dark"], 즉 <html>의 속성만 본다. <section>의 속성은 무시되므로 b도 꺼진다. 같은 이유로 b 근처의 토큰 색도 light 그대로다.

2. 정의를 아래처럼 바꾸면 dark:opacity-80은 어떤 CSS가 될까?

"@custom-variant의 두 형태"의 주의 상자와 "&와 @slot이 채워지는 과정"을 쓴다. 

-  &:where(:root[data-color-scheme="dark"], :root[data-color-scheme="dark"] *) { @slot; }
+  &:where(:root[data-color-scheme="dark"], :root[data-color-scheme="dark"] *) { color-scheme: dark; }
답 보기

속성 갈래의 규칙은 opacity: 80% 대신 color-scheme: dark를 담는다. @slot이 없는 자리에는 유틸리티의 선언이 들어가지 않고, 블록에 직접 쓴 선언만 나온다. media 갈래에는 @slot이 남아 있으므로 그쪽 규칙은 opacity: 80% 그대로다. 결국 <html data-color-scheme="dark">에서는 OS가 light일 때 dark:opacity-80이 opacity를 바꾸지 않는다.

출처

컴파일 결과는 @tailwindcss/node 4.3.5로 직접 컴파일해 얻었다(기본 dark:, 한 줄 형태, 이 저장소의 블록, @slot을 뺀 블록, dark:hover:와 md:dark:). 선택자 매칭은 Chrome 155에서 element.matches()로, 명시도에 따른 결과는 같은 브라우저에서 getComputedStyle로 확인했다. Tailwind 문서는 @slot과 블록 형태를 설명하지 않으므로, 이 두 가지는 컴파일 결과만을 근거로 한다.

  • Tailwind CSS, Functions and directives: @custom-variant로 프로젝트에 variant를 더한다는 것과 한 줄 형태의 예
  • Tailwind CSS, Dark mode: 기본 dark:는 prefers-color-scheme을 쓴다는 것, dark를 덮어써 수동 전환을 지원하는 예
  • Tailwind CSS, Compatibility: v4가 기대는 브라우저 버전(Chrome 111, Safari 16.4, Firefox 128)
  • MDN, :where(): 선택자 목록 중 하나에 맞으면 매칭되고 명시도는 항상 0이며, :is()는 가장 높은 선택자의 명시도를 가진다는 것. 2021년 1월부터 주요 브라우저에서 쓸 수 있다는 것
  • MDN, Universal selectors: *는 종류와 상관없이 요소에 맞는다는 것
  • MDN, Descendant combinator: 공백이 조상을 가진 요소를 고르는 결합자라는 것
